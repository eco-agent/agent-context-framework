# Registry 0.9.3: repository-context resume

## Status

Accepted.

## Decision

The project-scoped `repo_context` MCP table no longer sets `cwd = "."`.
Codex starts the server in the task repository that selected the project config.
The relative entry point and `--root .` argument then resolve against that task
repository.

Codex Desktop runs a long-lived app process. Its working directory is not the
task repository. Passing an explicit relative working directory made the child
process depend on the app process directory. Node exited before it could answer
the MCP initialize request, and Codex reported a closed connection.

The server remains required. A missing runtime or a genuine MCP initialization
failure still stops task startup. The existing startup and tool timeouts remain
unchanged.

## Preservation map

| Behavior | Disposition |
| --- | --- |
| Required MCP startup | Retained |
| Project-local runtime entry point | Retained |
| Portable relative paths | Retained |
| Read-only tool allowlist | Retained |
| Explicit relative MCP working directory | Removed |
| Codex task working directory inheritance | Selected |

## Boundary contract

Codex owns process launch, timeout, and the final startup error. The ACF config
selects the command, arguments, allowlist, and required status. ACF does not add
a retry because Codex already reports the terminal initialization failure once.

The focused installation test owns the stored config check and MCP protocol
probe. It requires the `cwd` member to be absent, starts the installed server in
the fixture repository, completes initialize, lists the tool, and reads a file.
Codex Desktop owns the final task-resume observation.
