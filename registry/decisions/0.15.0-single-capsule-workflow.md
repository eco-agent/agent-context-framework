# Registry decision 0.15.0: single capsule workflow

## Decision

ACF has one tracked distribution artifact at `.codex/acf/capsule.acf`. The
capsule contains the selected component closure, source bytes, and the hashes
that authorize tracked activation files. No project config or sidecar lock is a
second authority.

`agent-context pack` chooses the direct components, always includes `core`, and
writes the capsule plus tracked activation files through one recoverable
transaction. With no component arguments, it preserves the current selection or
selects `core` for a new project.

`agent-context sync` verifies the capsule and tracked activation before it
reconciles ignored projections. Codex discovers skills below `.agents/skills`.
Runtime bundles live below `.codex/acf/runtime/<tree-hash>`. The ignored receipt
at `.codex/acf/receipt.json` records the exact generated files. Short transaction
recovery data lives below ignored `.codex/acf/state/` and disappears after
recovery.

`agent-context diff` compares two valid capsules and reports semantic changes
and restart needs. Unequal capsules are a successful comparison, not a command
failure.

The old init, add, update, remove, capsule subcommands, external project config,
external installation lock, sidecar capsule lock, and migration command are not
compatibility paths. This revision removes them.

## Git workflow

Humans own the `development` integration branch. Agents start a
`codex/<task>` branch from its resolved commit, use one writer in the current
checkout, push that task branch, and open a pull request to `development`.
Agents never merge and never commit directly to `development`.

Linked worktrees are not part of the agent workflow. A remote branch separates
history but cannot protect files in a shared checkout from concurrent writers.

Task work records are no longer mandatory. Durable decisions belong in their
canonical documents. Ignored recovery state is allowed only when an interrupted
transaction cannot recover from Git and the filesystem alone.

## Ownership and failure behavior

The capsule is the authority for selection and generated content. The ignored
receipt may authorize replacement only when every recorded file still matches
its hash. Drift, unexpected files, symbolic links, a corrupt capsule, or an
incomplete transaction blocks writes and reports the exact path.

The framework repository keeps authoring sources below
`.codex/acf/runtime-source`. Downstream projects receive those bytes only inside
the capsule and materialize them below the ignored runtime directory.

## Superseded decisions

This decision supersedes the installation and migration workflow in 0.14.0,
0.14.1, and 0.14.2. It also replaces the push authority and worktree rules from
0.9.1 and 0.12.0. Their historical evidence remains unchanged.

## Verification

Focused tests cover deterministic packing, the embedded activation lock,
semantic diff, idempotent sync, fresh-clone bootstrap, generated-file drift,
corrupt capsules, and transaction recovery. Registry generation checks the
canonical policy projections and source hashes. The final acceptance command
records the exact framework and downstream fixture revisions after the
implementation commit.
