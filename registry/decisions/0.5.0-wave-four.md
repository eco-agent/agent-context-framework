# Registry 0.5.0 — Wave 4 Codex interface

## Decision

Package the project-local Codex interface as independently selectable
`codex-agents`, `codex-hooks`, and `codex-repo-context` components plus a
dependency-only `codex-runtime` convenience bundle. Keep `repository-policy`
independent. All installed Codex commands and runtime references remain inside
the target repository.

Introduce `toml-members` and `json-array-items` as closed structured ownership
operations. They own only declared TOML scalar/table paths and identified JSON
array items, preserving unrelated project configuration throughout install,
update, removal, recovery, and local modification.

The agent profile is explicit and versioned with this component selection.
Hooks remain inert without a scoped session binding and fail closed when a
binding exists but is invalid. Repository context reuses the bounded isolated
core behind one thin read-only MCP stdio adapter with an explicit authorized
root and fixed normal limits.

## Protected invariants

- `codex-interface-precise-structured-ownership`
- `codex-interface-explicit-agent-profile`
- `codex-interface-dormant-unbound-hooks`
- `codex-interface-fail-closed-invalid-bindings`
- `codex-interface-bounded-authorized-repo-context`
- `codex-interface-project-local-references`
- `codex-interface-host-manifest-neutrality`
- `codex-interface-wave-boundary`

## Source ownership

- `.agent-context/runtime` remains canonical for runtime root, shared, hooks, and
  repository-context source and isolated dependency state.
- `registry/sources/codex` owns the canonical installed agent, hook, and MCP
  configuration sources and project launch entrypoints.
- `.codex/config.toml` is shared only through precise TOML member/table ownership.
- `.codex/hooks.json` is shared only through identified event-array item ownership.

## Exclusions

- `repository-policy` is not a dependency of `codex-runtime`.
- No objective kernel, ledger, scheduler, queue, database, runner, task envelope,
  Codex SDK workflow, long-running agent loop, or objective fixture is distributed.
- No binding producer, user-global configuration, inline hooks, host package
  graph change, deployment, publication, or push is part of this revision.
