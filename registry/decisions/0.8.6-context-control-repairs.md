# Registry 0.8.6: context control repairs

Registry `0.8.6` repairs behavioral controls weakened while framework prose was
rewritten. It also makes installed instruction drift and prose-check omission
fail deterministic checks.

## Status

Accepted.

## Decision

The Agent Context Framework keeps the plainer prose introduced in `0.8.4` and
`0.8.5`, with these controls restored:

- Codex workflow roles need explicit permission for broader filesystem or
  network access. Technical access never authorizes a consequential external
  action.
- TypeScript escape hatches need four recorded proofs, including a scope narrower
  than the surrounding domain.
- Canonical root instruction regions and canonical role prompts must match their
  installed copies exactly.
- The full repository-work policy uses the core package, vendoring, provenance,
  and submodule rules without weaker wording.
- Diagnosis, frontend design, product adoption, session review, TypeScript
  modeling, and Codex workflow skills retain their stopping, ownership,
  acceptance, and completion checks.
- Every changed-file verification profile runs `agent-prose` on model-facing
  files selected by repository policy.
- Work records are temporary task state. A completed record remains only when it
  still owns required evidence that has not moved to a canonical decision or
  handoff.

## Owners

| Decision | Owner |
| --- | --- |
| Skill permissions and completion guards | Canonical skill source |
| Installed instruction equality | Context governance |
| Vendoring and submodule policy | Repository-work instruction source |
| Changed-file prose selection | Repository policy |
| Work-record closure | Framework work policy |

## Consequences

Refreshing a source hash cannot hide deletion of a protected safety sentence.
Changing an installed role prompt or root instruction without changing its
canonical source fails governance. Normal task and branch verification can no
longer omit the prose check for changed model-facing files.

The prose check remains deliberately small. It reports five exact writing
conflicts and does not judge general writing quality. Technical documentation
continues to use its separate repository-selected check.

This decision supersedes the `0.8.4` statement that agent prose is absent from
verification profiles. The explicit file-list command remains available for
focused skill feedback.

## Verification

- Skill structural validation and direct agent-prose checks cover the six
  repaired skill entrypoints.
- Context-governance tests alter root instructions, role prompts, vendoring
  policy, and restored skill guards and require each alteration to fail.
- Repository-policy tests cover changed-file selection and require every
  verification profile to include `agent-prose`.
- Registry construction checks canonical hashes and projections.
- The repository-policy package passed 39 tests. The context registry and
  governance suite passed 23 tests.
