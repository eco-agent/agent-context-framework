# Registry decision 0.17.0: repository registry interface

## Decision

ACF provides a local browser interface for its machine-level repository
catalog. `acf repo ui` starts the interface on a loopback address and opens it
in the default browser. `--no-open` leaves browser launch to the operator, and
`--port` selects a fixed port when another process must know the address.

The interface adapts the final component-installation shell from ACF commit
`d1dd2fb7f139461fa824c79f2d6e134331d05d7a`. A searchable repository list owns
the left pane. The selected repository's live status, capsule identity,
component closure, projection counts, and issues occupy one inspector pane.
Narrow layouts place the repository list above the inspector. The removed
component installation model and source editor do not return.

The browser does not derive repository state. The server calls the catalog
owner for registration, observation, sync, and removal. Refresh never writes.
Register, per-repository sync, sync all, and forget are explicit operator
actions.

## Local authority boundary

The server binds only to `127.0.0.1`. A random launch token authorizes the
document and every API request. The initial page removes the token from the
address bar after capture. Responses disable caching, framing, referrer
forwarding, and content-type sniffing. The server accepts at most 64 KiB per
JSON request and rejects unknown registration fields.

The catalog's existing path validation remains the authority for browser-entered
repository paths. Registration cannot enroll a missing directory, a non-ACF
repository, the user home, a filesystem root, or a path that contains the
catalog. Forget removes only the catalog record.

One in-process queue serializes UI mutations. Each repository's transaction
boundary remains the final one-writer guard when a CLI process and the UI race.
The UI reports the resulting blocked or failed state instead of retrying.

## Presentation ownership

The current repository has no frontend component library. The interface uses
native buttons, inputs, forms, lists, and definition lists. It retains the old
installer's compact sidebar, active-row navigation, fixed repository context,
and separate loading, empty, error, populated, focus, active, and disabled
states without restoring the removed React and shadcn dependency set.

## Verification

Focused tests cover loopback binding, launch and API tokens, static delivery,
empty state, registration, removal, and strict request decoding. Catalog and
CLI tests cover the single-repository sync owner and UI argument parsing.
