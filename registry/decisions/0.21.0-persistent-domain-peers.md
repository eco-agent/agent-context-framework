# Project decision: persistent domain peers

## Status

Accepted

## Context

The prior role configuration made Sol High the default and treated Sol and Luna as disposable subagents of one primary task. The workflow described in `docs/conversations/sol-luna-policy.md`, with the maintainer's later corrections, uses continuing Sol Medium tasks as domain owners. Astra Medium monitors and delegates only during an invoked pass because continuous supervision wastes input tokens and duplicates work already visible in the owning tasks.

Codex stores task identity and history natively. The App Server exposes task creation, listing, reading without resuming, resumption by task ID, stable user-facing names, goals, status events, and active-turn steering. ACF should use those records instead of creating another conversation archive.

## Decision

Persistent Codex tasks own project domains. Sol Medium is the normal user interaction point and retains the domain's decisions, corrections, and unfinished work.

A responsibility has one stable domain key, one pinned task title, and one native task ID. The task ID is the identity. The title is the lookup label and remains stable while that task owns the domain. Before creating a task, list the project's pinned tasks and reuse the existing exact domain owner. If no owner exists, create one and pin it. If several tasks claim the same domain, stop and ask the user to choose the owner. Do not create another claimant.

Astra Medium runs one bounded monitoring and delegation pass when the user invokes it, a Sol owner asks for cross-domain judgment, a shared contract changes, verification fails without an explanation, ownership conflicts, work stalls, or a review boundary is reached. The pass reads only the affected task summaries and new evidence, sends the required messages, optionally waits once for a dispatched result, records the outcome, and stops. It does not poll continuously, create a recurring automation, or reread unchanged tasks.

Luna xHigh handles ordinary bounded read-only retrieval. Luna Max handles a small independent read-only investigation when the additional inference is worth its cost. Luna output is evidence. The requesting Sol owner or invoked Astra monitor decides what follows.

## Affected invariants

- `persistent-domain-owner`
- `stable-responsibility-reuse`
- `invoked-astra-monitoring`
- `read-only-luna-evidence`
- `one-active-writer`
- `revision-bound-verification`

## Alternatives considered

- A continuously running Astra supervisor was rejected because it spends tokens when project state has not changed.
- A central Astra conversation for all user interaction was rejected because long-horizon domain context belongs with the Sol owner the user is changing.
- Disposable Sol implementation subagents were rejected as the default because they discard the context and corrections that make continuing domain ownership useful.
- A second ACF conversation database was rejected for this slice because Codex already persists task IDs, names, history, and status. ACF may add operational records later only for state the native task store cannot own.

## Consequences

- Users work directly in the relevant Sol Medium task.
- Astra can create or redirect domain tasks, but it does not mediate routine work.
- Pinned task titles form the project responsibility index. Native task IDs prevent identity from depending on a mutable title.
- The workflow must treat duplicate domain owners as a conflict rather than choosing the newest task.
- Waiting follows task events or one bounded wait after dispatch. Unchanged state produces no new monitoring turn.
- Repository writing still follows one branch and one active writer.

## Propagation

- `registry/sources/codex/agents.toml` and its role files own model profiles.
- `.codex/skills/coordinate-persistent-tasks/` owns the native task workflow.
- `registry/sources/instructions/core.md` routes domain work and evidence requests.
- The `codex-agents` registry component installs the role profiles and workflow skill.
- Governance requirements and installation tests protect the role split, read-only Luna boundary, stable reuse rule, and finite Astra pass.

## Verification

- Registry generation produces the expected role files, workflow skill, and project configuration.
- Governance rejects removal of the read-only Luna boundary, exact-owner reuse rule, or finite Astra stopping condition.
- Installation tests confirm Sol Medium, Luna xHigh, Luna Max, absence of the Sol worker, and installation of the persistent-task skill.
- The agent-prose check passes for every changed model-facing file.
