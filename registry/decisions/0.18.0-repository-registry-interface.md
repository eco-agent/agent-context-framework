# Registry decision 0.18.0: repository registry interface

## Decision

ACF provides a local browser interface for its machine-level repository
catalog. `acf repo ui` starts the interface on a loopback address and opens it
in the default browser. `--no-open` leaves browser launch to the operator, and
`--port` selects a fixed port when another process must know the address.
The root package publishes `tools/dev-tooling/bin/acf.mjs` as its `acf` command,
so `pnpm link --global` exposes the checkout on `PATH`.

The interface is a TanStack Start application built in SPA mode. A searchable
repository table owns the primary surface. The selected repository's live
status, capsule identity, component closure, projection counts, and issues
occupy one inspector. Narrow layouts stack the same repository and inspector
model. The removed component installation model and source editor do not
return.

The browser does not derive repository state. The server calls the catalog
owner for registration, observation, sync, and removal. Refresh never writes.
Register, per-repository sync, sync all, and forget are explicit operator
actions.

## Local authority boundary

The server binds only to `127.0.0.1`. A random launch token authorizes the
document and every API request. The initial page removes the token from the
address bar after capture. Responses disable caching, framing, referrer
forwarding, and content-type sniffing. The server accepts at most 64 KiB per
JSON request and rejects unknown registration fields.

The browser fetches the current desktop wallpaper as an authenticated image
blob. It never receives the wallpaper's filesystem path. The server detects
the image format from its bytes because the Windows wallpaper cache has no
extension. If the cross-platform wallpaper helper fails on Windows, the server
reads the OS-maintained `%APPDATA%/Microsoft/Windows/Themes/TranscodedWallpaper`
cache. An absent or unsupported image leaves the interface on surface 1.

The catalog's existing path validation remains the authority for browser-entered
repository paths. Registration cannot enroll a missing directory, a non-ACF
repository, the user home, a filesystem root, or a path that contains the
catalog. Forget removes only the catalog record.

One in-process queue serializes UI mutations. Each repository's transaction
boundary remains the final one-writer guard when a CLI process and the UI race.
The UI reports the resulting blocked or failed state instead of retrying.
The server waits for the browser process to spawn. A launch failure becomes a
CLI warning instead of an unhandled process event. The loopback server remains
available at the printed URL.

## Presentation ownership

`tools/repository-ui` owns the React source and publishes its built static SPA
into `tools/dev-tooling/repository-ui`. The loopback server remains the only
runtime process and keeps all filesystem authority.

Fluid Functionalism's Surfaces and Base UI ScrollArea sources are pinned to
commit `c0b2b2f79928151d7558cb4e6bc3f83263d2d4f6` under the upstream MIT license.
The Surfaces ladder replaces hard pane and table borders. The ScrollArea owns
scrollbars, touch-native overflow, and `scroll-fade` utilities. The UI does not
use `tw-fade`. TanStack Start structure follows the official TanStack Router
example at commit `ae68535929043607d4ee9438f8ae401f3a064862`, also under MIT.

The current desktop wallpaper fills the background. The upper portion remains
visible, then a dark scrim reaches surface 1 before repository data begins.
The navigation uses surface 2, the selected row uses surface 3, and the
inspector uses surface 4. Native buttons and inputs keep their browser semantics.

## Verification

Focused tests cover loopback binding, launch and API tokens, generated asset
delivery, CSP hashes for Start's inline bootstrap, empty state, registration,
removal, strict request decoding, extensionless wallpaper streaming, Windows
fallback resolution, and the no-wallpaper case. The UI build runs Start's
production build and strict TypeScript checking. Catalog and CLI tests cover
the single-repository sync owner and UI argument parsing.
