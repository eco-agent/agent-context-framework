# Registry 0.8.1: baseline writing policy

Registry `0.8.1` adopts the Unslop instruction set as protected core policy.
The rules apply to all agent-authored prose rather than only documentation or
user-facing reports. The 30-component topology and every dependency edge remain
unchanged.

## Decision

- Put the writing rules in the canonical core instruction source. Every profile
  already includes core, so the rules do not depend on skill discovery or task
  routing.
- Apply them to responses, plans, tool prompts, handoffs, work records, reviews,
  commit messages, and documentation.
- Preserve exact quotations, copied source text, code, protocol payloads, and
  machine-readable syntax. The rules govern prose written by the agent.
- Adopt the user-supplied Unslop text from `cursor/plugins` revision
  `fd6dd6f7276956a532bb78a748a8d2818b6eb5f4` under MIT. Keep its process and all
  31 patterns intact. Only the skill frontmatter and heading levels change to fit
  the core document.
- Keep the documentation instruction source focused on reporting completeness,
  disclosure, and safe review. Do not duplicate the writing rules there.
- Keep ASD English and the technical-prose checker unchanged. They still handle
  deterministic technical-document findings when a repository configures them.

## Protected semantics

- `all-agent-authored-prose`
- `meaning-and-tone-preservation`
- `human-voice-without-ai-tells`
- `concrete-plain-speech`
- `exact-text-and-syntax-preservation`
- `documentation-policy-separation`

## Preserved boundaries

- No component, bundle, dependency edge, capability declaration, or runtime
  behavior changes.
- No model-judged writing check is added.
- No copied source, exact quotation, code, protocol payload, or machine-readable
  data is rewritten to satisfy prose preferences.
- No consumer manifest, lockfile, migration, publication, deployment, or push is
  introduced.
