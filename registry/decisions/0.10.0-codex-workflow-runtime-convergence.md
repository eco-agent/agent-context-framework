# Registry 0.10.0: Codex workflow runtime convergence

## Status

Accepted.

## Decision

`packages/codex-workflow-runtime` owns the reusable workflow plan, evidence
ledger, bounded loop implementations, Codex turn transport, example, and mock
contract tests. `tools/codex-workflows` consumes that package and keeps only the
Objective-specific adapter, continuation binding, durable ledger, and runner.

The orchestration skill still installs a standalone TypeScript package. Its
`src`, `examples`, and `test` directories are exact projections of the canonical
package. `registry:build` repairs those directories and removes stale files.
`registry:check` is read-only and rejects any byte or file-inventory drift with
the repair command.

The standalone `package.json`, `tsconfig.json`, license, and source attribution
remain skill-owned because a copied package cannot depend on the framework
workspace graph.

## Preservation map

| Behavior | Disposition |
| --- | --- |
| Eight bounded workflow patterns | Retained in the canonical package |
| Standalone copy-and-run skill asset | Retained as an exact projection |
| Objective-bound thread continuation | Retained in `tools/codex-workflows` |
| Objective event IDs and durable JSONL recovery | Retained in `tools/codex-workflows` |
| Duplicate plan and loop implementations | Removed |
| Ambiguous `CodexWorkflowClient` name | Replaced by `PlanCodexClient` and `ObjectiveCodexClient` |
| Reviewer passes used as repair budget | Replaced by separate finite limits |

## Boundary contract

The OpenAI Codex SDK owns thread start, thread resume, structured output, and
cancellation. The canonical package owns plan validation, permission checks,
attempt budgets, evidence events, and finite loop transitions. The internal
package adds Objective identity and repository-context policy without widening
the reusable contracts.

The registry builder owns projection bytes and target file inventory. Governance
protects the canonical source hashes and required review path. The skill remains
the consumer entry point and must not become a second source of runtime logic.
