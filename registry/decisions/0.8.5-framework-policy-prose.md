# Registry 0.8.5: framework policy prose

Registry `0.8.5` rewrites ACF-authored instruction blocks in ordinary language.
It keeps the same component graph, capabilities, policy owners, and behavioral
requirements.

## Decision

- Rewrite the canonical core, work, verification, documentation, engineering,
  TypeScript, frontend, Tailwind, repository-policy, and session-quality
  instructions.
- Keep the imported Unslop body unchanged.
- Replace compressed lists and overloaded bullets with connected instructions.
  Use paragraphs where sequence or ownership matters, and keep lists only when
  the reader needs an actual set.
- Preserve every skill route, authorization boundary, Git rule, verification
  command, frontend constraint, repository-policy requirement, and disclosure
  duty.
- Continue to treat policy text as rules rather than a response template.

## Protected semantics

- `unslop-source-preserved`
- `ordinary-framework-policy-prose`
- `git-isolation-and-cleanup-preserved`
- `verification-authority-preserved`
- `frontend-evidence-and-adoption-preserved`
- `repository-policy-ownership-preserved`
- `skill-routing-preserved`
- `reporting-disclosures-preserved`

## Preserved boundaries

- The imported Unslop process and its 31 patterns do not change.
- Worktree ownership, checkpoint commits, stash prohibition, vendoring rules,
  and global Git configuration policy do not change.
- Frontend design selection, established-product adoption, asset handling,
  mobile treatment, interaction states, and styling constraints do not change.
- Test authorization, focused verification, final acceptance, and reporting
  requirements do not change.
- No template, hook, compaction behavior, skill behavior, runtime code,
  component, dependency, capability, package lock, migration, publication,
  deployment, or push is added.
