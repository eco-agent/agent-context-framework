# Registry 0.8.4: agent prose hotspots

Registry `0.8.4` reduces the amount of compressed policy prose shown during skill
selection and execution. It also gives model-facing Markdown a separate
deterministic check. The component list does not change. Skill authoring no
longer depends on the technical-document skill.

## Decision

- Review every ACF skill description and keep each one to a short routing
  sentence. Three descriptions were already short enough and remain unchanged.
- Rewrite the orchestration, TypeScript state-modeling, frontend design, session
  review, diagnosis, and established-product skills in ordinary language.
  Preserve their permissions, stopping conditions, required checks, and linked
  references.
- Prune the skill-authoring entrypoint so it follows the same prose check it
  recommends.
- Name the orchestration runtime helpers directly in the loop reference instead
  of teaching metaphorical loop names as prose.
- Add `check-agent-prose` for explicitly named model-facing Markdown files. It
  reports a small set of visible Unslop conflicts and does not judge tone,
  meaning, or correctness.
- Keep `check-technical-prose` for technical documentation selected by repository
  policy. Do not apply its ASD-style contraction and punctuation rules to prompts,
  handoffs, role instructions, or skills.
- Declare `agent-prose-check` as a recommended skill-authoring capability. A
  repository may provide another command with the same purpose.
- Remove `skill-write-technical-prose` and its runtime capability from the
  skill-authoring component. Engineering still owns technical-document routing.

## Protected semantics

- `short-skill-catalog-descriptions`
- `plain-selected-skill-instructions`
- `plain-skill-authoring-instructions`
- `skill-permissions-and-stops-preserved`
- `runtime-helper-names-are-concrete`
- `agent-prose-check-is-mechanical`
- `technical-prose-is-for-selected-documentation`

## Preserved boundaries

- Skill invocation remains automatic where it was automatic before this change.
- The diagnosis skill still separates investigation from authorization to fix.
- Frontend design still settles one design before implementation specialists
  begin work.
- The orchestration runtime, SDK version, workflow limits, and tests do not
  change.
- The new prose check runs only when called with explicit Markdown files. It is
  not added to a verification profile or acceptance run.
- No model-judged check, external dependency, component, package lock change,
  migration, publication, deployment, or push is added.
