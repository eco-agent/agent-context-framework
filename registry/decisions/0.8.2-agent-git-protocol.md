# Registry 0.8.2: agent Git protocol

Registry `0.8.2` replaces size-based worktree advice with a branch-first Git
transaction model. The 30-component topology and every dependency edge remain
unchanged.

## Decision

- Let a branch own each logical work stream. Resolve and record one full baseline
  commit before creating it. A moving branch name is not durable evidence.
- Use the current checkout for serial work. Create a linked worktree only for
  concurrent work or an isolated check. Agent-created worktrees are ephemeral,
  and cleanup removes only the exact clean worktree owned by the run.
- Replace agent stashes with visible checkpoint commits. Agents never place task
  or user state in the repository-wide stash ref.
- Use `git subtree` for repository-shaped vendored source with an upstream update
  lifecycle when the host supplies the contrib command. Preserve direct pinned
  copies for selected-file adoption. Avoid submodules unless a project contract
  requires their independent checkout and release lifecycle.
- Give Git-backed durable workflows a private ref namespace under
  `refs/agent-context/runs/<run-id>/`. Update stage refs with expected old object
  IDs and record the same identities in the workflow ledger. Refs preserve local
  reachability. The ledger owns durable stage evidence.
- Keep reviewer repairs as fixup commits until authorized finalization. Use
  `range-diff` as a human review view, not machine-stable output. Capture a
  pre-finalization ref before autosquash and rerun required checks after history
  rewriting.
- Use `merge-tree --write-tree --quiet` for a worktree-free integration preflight.
  Record both tips and repeat the preflight if the integration target moves.
- Treat `rerere`, `zdiff3`, and sparse checkout as project decisions. The
  framework does not mutate global Git configuration. Sparse checkout is an
  optimization, not a scope, authority, or security boundary.
- Keep Difftastic, Git Town, Graphite, and Jujutsu optional. They do not become
  framework dependencies, required agent interfaces, or correctness gates.
- Declare Git as a required core runtime capability. Declare it as recommended
  on the optional orchestration skill because only its Git-backed branch needs
  the transaction reference.

## Protected semantics

- `branch-owns-work-stream`
- `immutable-baseline-commit`
- `ephemeral-concurrency-worktree`
- `checkpoint-commit-not-stash`
- `ledgered-private-stage-refs`
- `visible-review-fixups`
- `worktree-free-integration-preflight`
- `checked-non-forced-cleanup`
- `no-global-git-mutation`

## Preserved boundaries

- The objective kernel still does not create, select, persist, or clean work
  directories.
- No Git wrapper, scheduler, hosted review system, VCS abstraction, global
  configuration mutation, or automatic push is added.
- No private ref is treated as portable or durable workflow storage.
- No worktree path, sparse checkout, or branch name becomes an authority or
  security boundary.
- No component, bundle, dependency edge, package manifest, lockfile, migration,
  publication, deployment, or push changes. Only the Git capability declarations
  change.
