# Registry 0.5.1 — distribution hardening

Registry `0.5.1` preserves the complete `0.5.0` component and dependency
topology while closing the release-evidence gaps found by the Phase 8 and Phase
9 audits.

## Decision

Project-authored distributable components are licensed under MIT. Every project
license declaration names the root `LICENSE` and the generated registry records
its exact SHA-256. The non-removable `core` component installs those bytes as
`.agent-context/LICENSE.agent-context-framework`, so every materialized project
retains the project notice without adding a component or dependency edge.
Third-party component declarations continue to name an exact repository revision
and installed notice, and now also record the exact notice hash.

External packages used by the isolated runtime must identify an exact Git commit
or an integrity-pinned immutable npm archive and declare the notice files carried
by that package. This revision corrects the MCP server source commit, replaces
mutable Zod and TypeScript references with their package source commits, and uses
the immutable npm archive as the source identity for `@types/node`, whose package
metadata exposes no Git commit.

Distributable executable use is checked against the selected component closure.
The Codex hooks contract declares Git and a platform shell; the session optimizer
declares Git. The existing Node, Corepack, and ripgrep declarations remain owned
by their established components.

## Preserved invariants

- Registry artifact source bytes remain content-addressed.
- The exact Wave 4 component graph is unchanged.
- `codex-runtime` remains dependency-only and excludes `repository-policy`.
- Project installation remains host-manifest neutral.
- Third-party source attributions and retained notices remain component-local.
- Objective kernels, schedulers, queues, databases, task envelopes, and
  long-running agent loops remain outside every distributable component.

## Exclusions

- No new component, dependency edge, runtime package, compatibility schema,
  host dependency, orchestration topology, deployment, publication, or push.
- This record captures the selected license and reproducible provenance; it is
  not legal advice.
