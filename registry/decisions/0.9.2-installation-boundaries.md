# Registry 0.9.2: installation boundaries

## Status

Accepted.

## Decision

The installer checks the complete registry before planning or writing. A stale
artifact hash now blocks the operation even when the user did not select the
component that owns the stale source.

Markdown sections use a blank line after their opening marker. This is the
canonical form accepted by Markdown formatters. Updates rewrite the older
single-newline form without changing the managed section content.

Fresh installations seed LF rules for framework-managed paths. Projects that
already own `.gitattributes` keep their file unchanged. Oxfmt projects can add
the `integration-oxfmt` component, which owns only the `.agent-context/**`
ignore value and preserves every project-owned ignore.

Setup has an optional `--exit-after-install` lifecycle. It closes only after the
successful installation response has finished. Blocked and failed attempts
leave the server running so the user can repair the problem or retry.

The codebase inventory fixture creates its ignored probe file at test time. The
registry no longer depends on force-adding a path that its own fixture ignores.

The preserved-instruction check now follows the explicit-push wording accepted
in registry 0.9.1. The prior check still searched for the removed "never push"
sentence, so it could not enforce the accepted replacement.

## Preservation map

| Behavior | Disposition |
| --- | --- |
| Default interactive setup lifecycle | Retained |
| Blocked setup repair and retry | Retained |
| Project-owned formatter ignores | Retained |
| Existing `.gitattributes` files | Retained |
| Legacy Markdown marker spacing | Replaced during update |
| Packaged ignored fixture probe | Replaced with test-time creation |

## Boundaries

- Registry consistency owner: `context-registry-builder`. Observation: every
  registry-dependent CLI and setup operation runs the complete build comparison
  and governance check. Grace path: `recover` and `bootstrap-runtime` remain
  available when the registry is stale.
- Setup lifecycle owner: `setup-server` reports a successful applied event only
  after the HTTP response finishes. The CLI owns signal handling and server
  shutdown. Grace path: omit `--exit-after-install` for the interactive server.
- Formatter ownership owner: `json-array-values` identifies exact scalar values
  inside a declared JSON array. It rejects duplicates and partial ownership.
  Grace path: do not select `integration-oxfmt` in projects that use another
  formatter.
- Line-ending owner: the core seed file creates `.gitattributes` only when the
  project has no file. Existing repositories keep project ownership and may add
  stricter rules.
