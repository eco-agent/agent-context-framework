# Registry 0.6.0 — framework feedback closure

Registry `0.6.0` corrects ownership, profile, and operator contracts discovered
during a full downstream installation without adding objective orchestration.

## Decisions

- Add `seed-file` as an explicit project-owned artifact operation and use it for
  `.agent-context/policy.json`. The framework seeds a missing file only when the
  component is newly selected; updates, overwrite, removal, and doctor never
  claim the project's later bytes or existence choices.
- Repository policy declares exact project contract paths. Core instructions make
  those declared contracts discoverable before implementation.
- Code changes require focused type and behavior verification by default. Broad
  repository and browser gates remain explicit acceptance actions.
- Keep generic frontend and responsive-CSS components technology-neutral. Move
  Tailwind-only instructions, scripts, and references into the exact
  `frontend-tailwind` dependency closure.
- Operator plan and inspection surfaces disclose direct versus transitive
  selection, installed footprint, capability requirements, drift, and dormant
  hook activation instead of presenting a flat component list.

## Preserved boundaries

- Project-authored distributable components remain MIT licensed, with pinned
  source, notice, and capability declarations governed as before.
- Objective kernels, schedulers, queues, databases, task envelopes, binding
  producers, Codex SDK workflows, and long-running agent loops remain outside all
  distributable components.
- No host package dependency, compatibility schema, inferred repository policy,
  publication, deployment, or push is introduced.
