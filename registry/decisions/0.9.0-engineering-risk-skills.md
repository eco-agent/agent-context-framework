# Registry 0.9.0: engineering risk skills

Registry `0.9.0` adds focused engineering owners for operational boundaries,
shared mutable state, and reader load. It also requires one representative
routing exercise for every distributed skill.

## Status

Implementation in progress.

## Decision

`design-operational-boundaries` applies when work changes a network,
persistence, process, queue, background-work, or service boundary. It defines
expected and exceptional failures, timeout and cancellation behavior, retry
safety, cleanup, one reporting owner, safe event context, and explicit
unverified outcomes. It does not introduce logging or telemetry infrastructure
when the project has none.

`separate-shared-state` applies when concurrent actors may write the same file,
key, record, branch, or in-memory object. Independent facts receive separate
write targets. A real canonical target uses the repository's existing atomic or
single-writer mechanism. Instructions do not count as concurrency control.

`reduce-reader-load` applies during refactors and changes to code with hard-to-
trace origins or mutation paths. It removes layers that own no decision, shrinks
mutable state scope, and retains boundaries that own validation, authority,
effects, failure translation, public contracts, or demonstrated alternate
implementations.

The `engineering` profile selects all three skills. Their catalog descriptions
remain narrow so ordinary code changes do not load every review concern.

The existing frontend skill now also selects for a novel user-facing
interaction whose representation or behavior is unsettled. The existing
TypeScript skill now derives shapes from authoritative schemas and strengthens
types where a looser type makes an operation partial. Neither change creates a
parallel owner.

`registry/sources/skill-routing-exercises.json` records one positive prompt, one
nearby negative prompt, the changed decision, an observation, and a grace path
for every packaged skill entrypoint. The registry builder checks strict schema,
unique ownership, exact skill coverage, and distinct prompts. These checks prove
that the release owns an exercise. They do not prove that a model followed the
skill. Bounded forward-use review owns that semantic result.

## Owners

| Decision | Owner |
| --- | --- |
| Runtime failure and reporting behavior | `design-operational-boundaries` |
| Concurrent mutable state ownership | `separate-shared-state` |
| Trace depth and mutable-state scope | `reduce-reader-load` |
| Novel frontend interaction routing | `frontend-design-discipline` |
| Type derivation and useful precision | `design-typescript-invariants` |
| Exercise schema and exact skill coverage | Registry builder |
| Exercise meaning and forward-use result | Skill author and maintainer review |
| Packaging, attribution, and installation | Registry source and installer |

## Source adoption

The shared-state and reader-load skills adapt selected pstack principles from
`https://github.com/cursor/plugins` at
`46125561306434d8a1d7745d540d8932ab0cd2a2` under the MIT license. The
TypeScript refinements adapt two principles from the same pinned source. Each
affected skill installs its source record and license notice.

The operational-boundary skill uses the logging source at
`8aa14dd16a1340a6049e6d7cd58e2ed52333a550` as design evidence only. Its
instructions were written independently because that repository does not
supply a complete license notice at the pinned revision.

## Consequences

Agents receive the missing engineering concern close to the task that needs it.
When the repository lacks an observer or concurrency mechanism, the skill makes
that gap visible and supplies a bounded next action. It does not hide the gap or
expand the task into infrastructure work.

Release coverage can no longer omit a distributed skill silently. The exercise
catalog remains repository-only because downstream projects do not need the
prompts to install or invoke skills.

The release does not add a production loop that invokes every skill. A later
post-diff risk router may use these focused owners without changing their
contracts.
