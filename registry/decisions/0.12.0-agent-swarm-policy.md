# Registry 0.12.0 agent swarm policy

Revision `0.12.0` replaces a bootstrap-era two-thread profile with routing based
on authority and task shape.

## Decision

Use GPT-5.6 Sol for the primary agent, general delegated work, and bounded
implementation. Use GPT-5.6 Luna Max only for scoped read-only investigation.
The primary starts independent scout lanes in parallel when a task contains two
or more questions that can return once. Scout output remains evidence until Sol
resolves contradictions and decides what becomes repository state.

Remove the project-owned agent concurrency scalar. The active Codex runtime and
provider own capacity. A project may configure a supported runtime limit when it
has measured evidence for one, but the framework does not replace runtime
capacity with a smaller fixed number.

Treat failed scout lanes as disposable work. Replace a transiently failed lane
once. After the replacement fails, Sol performs that investigation directly or
reports the missing evidence. The task must not wait indefinitely for broken
delegation.

Keep the worker role, but run it with Sol High. A delegated writer receives an
isolated worktree or exclusive ownership of the current branch and index until
the assignment ends. Luna never writes repository state, and two active writers
never share one file, index, branch, or record.

## Ownership and observation

- `registry/sources/instructions/core.md` owns routing, synthesis authority,
  retry behavior, and the single-writer rule.
- `registry/sources/codex/agents.toml` owns the three role declarations without
  owning runtime capacity.
- The role TOMLs own model selection, sandbox permissions, assignments, and
  return contracts.
- Codex interface doctor reports obsolete bootstrap fields and names the valid
  next action.
- Registry governance protects the model-facing rules and their installed
  projections.
- Agent-profile and installer tests prove model selection, read-only scout
  isolation, structured ownership, installation, diagnosis, and removal.

## Retained behavior

- The primary agent owns product and architecture decisions.
- Subagents cannot create other agents.
- Installed role files remain project-local and explicitly versioned.
- Installer updates and removal preserve unrelated Codex configuration.
- Project trust remains required before Codex loads project configuration.

## Rejected alternatives

- Increasing the fixed thread count would replace one unsupported number with
  another.
- Keeping Luna as a writer would make a lower-intelligence model responsible for
  repository decisions despite the available read-only boundary.
- Removing the worker role would let Codex fall back to a built-in role whose
  model and ownership contract are not selected by this component.
- Unlimited concurrent writers would move risk into Git and shared files instead
  of containing it at the authority boundary.
