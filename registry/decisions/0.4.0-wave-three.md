# Registry 0.4.0 — Wave 3 repository policy

## Decision

Package the Phase 5 isolated runtime foundation and policy package as two
components: internal `runtime-base` and public `repository-policy`.
`runtime-base` owns only runtime root files and the shared package.
`repository-policy` owns only the policy package and project-facing policy
configuration, invariant manifest, wrapper, and canonical instruction section.

The installed policy configuration begins in the explicit `unconfigured`
state. Repository inspection may report observations, but only a project-owned
edit can declare repository facts, tokenized commands, and named verification
profiles. Registry data cannot supply executable commands and component
installation does not bootstrap dependencies or build output.

## Protected invariants

- `repository-policy-explicit-facts`
- `repository-policy-explicit-profiles`
- `repository-policy-observation-only`
- `repository-policy-tokenized-commands`
- `repository-policy-runtime-isolation`
- `repository-policy-wave-boundary`

## Source ownership

- `.agent-context/runtime` remains the canonical source for runtime root,
  shared, and policy bytes.
- `registry/sources/policy` owns the installed configuration, invariant
  manifest, and project wrapper.
- `registry/sources/instructions/repository-policy.md` owns normative agent
  instructions and is projected exactly into the framework `AGENTS.md`.

## Exclusions

- No hooks or repository-context package is included in either Wave 3 component.
- No `.codex/config.toml`, `.codex/hooks.json`, Codex agent, or Wave 4 bundle is
  installed.
- No objective kernel, scheduler, queue, database, task envelope, orchestration
  loop, or objective fixture is distributed.
- No host manifest, host lockfile, deployment, publication, or push is part of
  this revision.
