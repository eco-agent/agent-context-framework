# Registry 0.14.1 capsule runtime completion

Revision `0.14.1` makes the independent repository-policy runtime executable
from a migrated context capsule. It preserves the `0.14.0` component graph and
capsule format.

## Decision

Package the existing policy CLI as a standalone project-owned runtime file.
Route the installed `.agent-context/policy.mjs` wrapper through the tracked
plain-Node capsule bootstrap. The bootstrap verifies lock v3, the capsule, and
the materialization receipt before it starts that entrypoint. Lock-v2 projects
use the same command and retain their direct expanded runtime path.

The downstream acceptance fixture selects `codex-runtime` and
`repository-policy` as independent direct components. This fixture composition
does not add a dependency edge between them.

## Preserved invariants

- `repository-policy` remains independent from `codex-runtime`.
- Runtime materialization remains content addressed and ignored by Git.
- Plain-Node bootstrap remains the only owner of lock-v2 and lock-v3 executable
  selection.
- The policy CLI keeps its existing operations, configuration paths, exit codes,
  and JSON output.
- Project installation remains independent from the host package graph.

## Verification

The policy bundle must rebuild byte for byte. A generated migrated acceptance
fixture must have no tracked expanded runtime, must rematerialize the policy
entrypoint through the bootstrap, and must pass both downstream runtime and
repository-policy commands without changing its Git revision or status.

## Exclusions

This revision does not add an updater, fleet manager, central configuration,
host launcher, deployment, publication, or push.
