# Registry 0.20.0: remote GitHub workstreams

## Status

Accepted.

## Decision

When the GitHub connector can write to a repository, agents perform non-trivial
coding work on a remote `codex/<task>` branch and expose it through a draft
pull request targeting `development`. They do not mutate the user's local
checkout in this mode.

`main` is the deployment branch. `development` is the human-owned integration
branch and the branch the user normally runs locally. Named branches carry
incomplete or alternate product behavior. Environment variables remain valid
for secrets and real environment-specific addresses, but not merely to reveal
work that can live on a branch.

The `github-workstreams` skill owns the connector procedure. It pins the
`development` commit, creates atomic multi-file commits with Git objects, moves
refs without force, opens the draft pull request early, and binds verification
to the exact observed commit.

This decision supersedes the local-checkout default in Registry 0.8.2 and the
explicit-push requirement in Registry 0.9.1 when the GitHub connector is
available. It retains their checkpoint, immutable-baseline, single-writer,
no-stash, no-force, and human-merge boundaries.

## Preservation map

| Behavior | Disposition |
| --- | --- |
| Full baseline commit before work | Retained |
| One branch and one writer per work stream | Retained |
| Small checkpoint commits | Retained |
| No stash, force push, autonomous merge, or deployment | Retained |
| Local task branch as the normal agent workspace | Replaced by a remote connector branch |
| Linked worktrees for agent isolation | Removed |
| Push only after a separate explicit request | Replaced by standing authority for the task branch |
| Pull requests target `development` | Retained |
| `development` as human-owned integration | Retained and tied to local execution |
| `main` as the deployment branch | Added |
| Branches instead of configuration-only feature selection | Added |
| Git-object commits and early draft pull requests | Added |
| User-owned local checkout in connector mode | Added |

## Boundaries

The canonical core instruction owns branch roles and local authority. The
`github-workstreams` skill owns connector operations.

The GitHub branch, commit graph, and draft pull request show whether the agent
kept work remote and bounded. A non-fast-forward ref rejection is the mechanical
conflict observer. Governance protects the skill and the canonical branch rules.

When the connector or its write authority is missing, the agent reports the
missing operation and leaves the local checkout unchanged. Local execution
requires an explicit user request.

## Verification

The registry build and governance checks must cover the new skill, invocation
metadata, routing exercise, canonical instructions, projections, and semantic
requirements. The repository agent-prose check must pass on every changed
model-facing file.
