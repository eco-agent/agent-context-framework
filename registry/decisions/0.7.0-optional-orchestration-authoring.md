# Registry 0.7.0 — optional orchestration authoring

Registry `0.7.0` makes bounded Codex SDK workflow authoring explicitly
selectable without adding an active orchestration runtime to any existing
component closure.

## Decision

- Add the leaf component `skill-orchestrate-codex-workflows`. It installs the
  complete project-authored skill package, generic TypeScript runtime template,
  loop catalog, UI metadata, and mock tests under
  `.codex/skills/orchestrate-codex-workflows`.
- Keep every existing component dependency unchanged. In particular, `core`,
  `engineering`, `typescript-engineering`, `repository-policy`, and
  `codex-runtime` do not select orchestration authoring transitively.
- Treat framework installation as inert source distribution. It does not
  install `@openai/codex-sdk`, change the consumer's package manifest or
  lockfile, create a workflow, produce a hook binding, or execute a model turn.
- Require Node.js, network access, and authenticated Codex execution when the
  installed skill is used. Capability declarations report requirements. The
  installer does not infer their availability.
- Protect the skill's fixed topology, finite budgets, evidence-before-transition
  rule, least-authority defaults, decoded control decisions, and explicit
  rejection of recursive role creation and quorum loops through maintainer-owned
  semantic governance.
- Treat the bundled JSONL ledger as a single-process audit record. It does not
  claim crash-safe workflow restoration, cross-process coordination, or the
  semantics of a scheduler, queue, or database.

## Source and licensing

- The generic workflow foundation was authored in this MIT-licensed repository
  and first recorded in commit `a6739f9eec888609e46200c26bc6f520059d3f82`.
  The repository-owned skill package is its distributable authoring source and
  carries a local copy of the framework MIT license.
- The template pins `@openai/codex-sdk` `0.145.0` as a package dependency. SDK
  bytes are not vendored or installed by the framework. The existing dependency
  adoption record and packaged full license preserve its source, integrity,
  Apache-2.0 license, and required notice terms.
- `tools/codex-workflows` is an expanded internal consumer with objective and
  product integrations. It is not a source artifact of this component.

## Preserved boundaries

- No existing bundle or profile acquires the new skill implicitly.
- Objective kernels, objective runtimes, schedulers, queues, databases, task
  envelopes, binding producers, adaptive agent hierarchies, sibling quorums,
  and long-running unbounded loops remain outside every distributable closure.
- Live Codex execution remains separately authorized and is not a registry,
  installer, setup UI, or default verification action.
- No compatibility layer, migration adapter, consumer manifest or lockfile edit,
  publication, deployment, or push is introduced.
