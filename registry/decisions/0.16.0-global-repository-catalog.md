# Registry decision 0.16.0: global repository catalog

## Decision

ACF keeps its machine-level repository catalog below
`$CODEX_HOME/acf/repositories`, with `~/.codex` as the default Codex home. Each
registered repository has one JSON record named by the SHA-256 hash of its
canonical absolute path. The record contains only its schema version, identity,
and path.

Separate records avoid a shared mutable repository array. Commands registering
different repositories can publish independently. Re-registering the same path
is idempotent. Forgetting a repository deletes only its exact catalog record and
never changes the repository.

Registration writes a complete temporary record in the catalog directory, then
publishes it with an atomic no-replace hard link. Competing registrations for
the same repository either publish the record or read the winner. Readers never
observe a partially written JSON document.

The global catalog inventories repositories. It does not duplicate or override
the capsule, repository policy, selected components, generated receipt, or Git
state. Those facts remain owned by each repository.

## Observation and control

`agent-context repo register` adds one repository after validating its capsule.
`repo list` reads the catalog. `repo status` derives live health from the capsule,
tracked activation, transaction state, receipt, runtime projection, and skill
projection. It stores no health snapshot.

Repository status is one of `current`, `sync-required`, `repack-required`,
`blocked`, `invalid`, or `missing`. Each non-current result reports the exact
files or validation errors that require attention.

`agent-context sync --all` processes registered repositories in deterministic
catalog order. One repository failure does not prevent observation or sync of
the remaining repositories. The command exits with attention after reporting
every result. Each repository's existing transaction boundary still owns its
writes and recovery.

Status and all-repository sync isolate malformed catalog records. They report
the record path and parse error, then continue with valid records. The strict
`repo list` command still rejects a malformed catalog rather than silently
omitting it.

The ordinary `pack` and `sync --cwd` commands remain the way to control one
repository. Global registration is explicit. A fixture, CI run, or repository
bootstrap must not silently enroll a path in a user's machine-level catalog.

## Boundaries

Registration resolves symlink aliases to one canonical path and rejects missing
directories, filesystem roots, the user home directory, and paths that contain
the catalog or sit below it. Catalog records never contain repository contents,
credentials, saved status, or timestamps.

Catalog operations resolve the nearest existing ancestor before using a path.
This catches a catalog symlink that leads inside the repository even when the
spelling of the supplied path appears unrelated.

Project-packed artifacts still may not reference user-global executables or
configuration. The host-level catalog is separate from the capsule and is not
distributed into repositories.

This revision does not scan arbitrary directories, clone repositories, mutate
Codex's `config.toml`, pack every repository, run verification, pull branches,
push branches, or merge pull requests.

## Verification

Focused tests cover Codex-home resolution, strict record decoding, canonical
identity, independent concurrent registration, idempotence, exact removal, and
all live repository states. CLI tests cover registration, listing, status,
forgetting, and all-repository sync arguments.
