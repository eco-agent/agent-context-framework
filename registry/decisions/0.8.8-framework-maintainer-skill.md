# Registry 0.8.8: framework maintainer skill

Registry `0.8.8` adds an automatically selected skill for changing Agent Context
Framework instructions, skills, registry components, governance, and generated
configuration.

## Status

Accepted.

## Decision

`maintain-agent-context-framework` treats existing instructions as active
constraints. An edit classifies affected behavior as retained, changed, removed,
or added. Only an explicit user request may remove or weaken a requirement.

Every changed behavior names one owner, a boundary, an observation, and a grace
path. The observation shows whether the agent stayed inside the boundary. The
grace path names the allowed next action when the primary path is blocked without
widening scope or weakening the rule.

The skill treats attention as a limited resource. Repeated drift first prompts a
check of instruction placement, competing live context, observation, and allowed
next actions. More repeated prose is not the default repair. Universal
requirements remain in the entrypoint, conditional detail moves to a routed
reference, and mechanically decidable facts move to existing checks or generated
artifacts.

Model-facing prose owns intent, permissions, judgment criteria, semantic
boundaries, exception meaning, and recovery. Deterministic code owns facts such
as syntax, schemas, paths, exact projections, hashes, dependency closure,
generated output, changed-file selection, and measured limits. Where both are
needed, prose owns the meaning and code reports only the proxy it can observe.

Instruction language is treated as behavioral input because agents copy its
voice. A skill frontmatter `description` is treated as a catalog trigger that
names applicable requests and distinguishes adjacent work.

The skill rejects new process unless it changes a model decision at the right
time or proves a boundary the model cannot observe reliably. It is packaged as
an optional leaf and is not added to a broad bundle.

## Owners

| Decision | Owner |
| --- | --- |
| Preservation, bounds, grace paths, and completion | Skill entrypoint |
| Prose-versus-code classification | `references/prose-and-enforcement.md` |
| Automatic selection | Skill frontmatter and `agents/openai.yaml` |
| Packaging | Registry source |
| Anti-dilution protection | Context governance |

## Consequences

Framework edits have a checkable semantic diff instead of relying on a line diff
or a general claim that meaning was preserved. A prohibition without a recovery
path is incomplete. A prose rule that can be decided from stored inputs should
move to an existing checker, while semantic judgment remains with the model or
human owner.

The skill does not add a validator or script. Existing registry, governance,
installation, structural skill, and agent-prose checks already own the
mechanical proof needed for this change.

## Verification

- Structural skill validation covers the new skill entrypoint and metadata.
- Agent-prose checks cover the skill, reference, decision, and work record.
- Context governance protects the trigger, preservation rule, bounded behavior,
  grace path, attention guidance, prose-versus-code boundary, and completion
  contract.
- Registry construction and an isolated installation test prove the skill is an
  optional leaf and installs with its exact source bytes.
