# Registry 0.3.0 — Wave 2 engineering context

## Decision

Package the seven existing engineering-context skills, four independently
selectable bundles, and their canonical templates and documentation
conventions. Repair only source portability defects required for downstream
installation. Keep runtime extraction and objective orchestration excluded.

## Affected invariants

- `engineering-independent`
- `engineering-inventory`
- `engineering-diagnosis`
- `engineering-reuse`
- `engineering-technical-prose`
- `typescript-engineering-explicit`
- `session-quality-explicit`
- `skill-authoring-explicit`
- `engineering-work-record`
- `engineering-type-contract`
- `engineering-project-decision`
- `engineering-documentation`
- `engineering-source-portability`
- `engineering-license-provenance`
- `objective-orchestration-excluded`

## Context fidelity

Wave 2 adopts the framework's existing skill directories and exact supporting
files. Changes are limited to removing framework-only command assumptions,
adding missing source attribution, and making one binary-classification
fixture compatible with the text-only materializer without changing what its
validator proves.

New instruction sections are canonical registry sources and exact framework
projections. New templates have one canonical source each. Existing frontend
sources, components, dependencies, and policy remain unchanged.

## Component boundaries

- `engineering` includes only general codebase orientation, causal diagnosis,
  reuse, technical prose, durable work/decision templates, and documentation
  conventions.
- `typescript-engineering` explicitly adds TypeScript invariant modeling and
  its type-contract template.
- `session-quality` includes only completed-session optimization.
- `skill-authoring` includes only skill-writing and technical-prose guidance.

None of these components installs runtime tooling, Codex integration, or
objective orchestration.

## Exclusions

- Frontend component changes
- Isolated runtime extraction
- Repository-policy packaging
- Codex agents, hooks, or repository context
- Objective kernel, runtime, scheduler, stores, runner, loops, and fixtures
