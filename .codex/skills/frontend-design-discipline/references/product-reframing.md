# Product reframing

Use this reference before choosing substantial topology, a visual thesis, or the
representation of meaningful product state.

## Design the subject, not the field

A schema describes stored values. It rarely identifies the product experience.
Determine the human subject, audience, task, and lived outcome before selecting a
visual object.

For example, `temperature: number` is an implementation fact. Domestic thermal
comfort may be the subject. Its world includes thermostat hardware, the resistance
of a physical dial, cold glass, moving air, blankets, fireplace light, compressor
hum, television glow, and the difference between an empty neutral room and an
inhabited comfortable one.

That subject can change composition, sound, motion, hierarchy, interaction,
visibility, or the represented environment. The source value need not become a
number, badge, progress bar, card, or gradient.

## Derive a representation thesis

Use the subject's real materials, instruments, artifacts, environments, and
vernacular. A useful thesis governs information architecture, terminology,
interaction, content, assets, and explanation. A visual theme that leaves the same
hero, card grid, capability sequence, and interaction model intact is styling, not
reframing.

Ask:

- What does the state mean in use?
- Which differences change a user decision or feeling?
- Does exact magnitude matter, or only regimes, direction, or extremity?
- Is the user monitoring continuously or glancing occasionally?
- Can the state alter an existing surface instead of creating another widget?
- Which parts of the subject's world explain real product behavior?

Metaphor is not permission to invent features. It must clarify evidenced content,
tasks, and capabilities. Operational precision, accessibility, and the user's actual
job take precedence over atmosphere.

## Counterfactual review

Remove the schema and current implementation from the mental model. Given only the
product requirements, representative states, and user tasks, would this same
representation be chosen independently?

If not, the design probably translated an implementation rather than understanding
the product.
